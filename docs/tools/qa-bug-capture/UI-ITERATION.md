# Extension 0.3 — screenshot and testing UX

Requested: current brand icon, minimal light popup with Screenshot / Start testing, click-or-drag viewport selection, compact annotation editor below image (color, draw, rectangle, arrow, text, blur, undo/redo, download), explicit cross-tab activity lock, centered icon testing dock with tooltips, anchored popovers/toasts, Pause/Resume, Finish removes controls.

Implementation gates:

1. Shared local editor, icon assets and screenshot selection; screenshot-only flow never attaches debugger. Crop coordinates mapped to screenshot pixels. Explicit visual review; blur baked into exported PNG, not a text-redaction claim. Raster editing remains local and memory bounded.
2. Worker lifecycle: one unfinished activity across tabs and modes. Screenshot phase/token tied to tab; popup offers Exit / Back to tab. Testing lock persists while paused/stopped until Finish/cancel. Pause excludes requests and preserves session identity; Resume starts new network acquisition without backfill. Cancel/close/reload cleanup explicit. Finish stops first and removes dock after successful local handoff.
3. Minimal light popup; fixed centered dock; floating panes/toasts positioned independently of dock dimensions. Searchable request panel with collapsible body, accessible icon actions and feedback.
4. Meaningful unit + temporary Chrome tests for selection/crop/editor history/download, popup states, cross-tab lock, pause/resume, dock anchoring, Finish cleanup, existing capture/handoff. Build extension + app, typecheck/lint/tests, exact artifact references and brand image sizes. Record actual checks and limits.

APIs checked: official Chrome action icons (PNG sizes), tabs.captureVisibleTab, activeTab and scripting. Selection is within the current web viewport, not the OS desktop or a full-page scroll capture. Browser internal pages remain unsupported. No extra host permissions or external assets. Existing app tokens and current SVG logo are the asset source. Screenshot mode should not require Chrome's debugging banner; testing still does.

Status: complete; verification and usage below.

## Using the update

Run `npm run build:qa-extension` if not already built. Reload the unpacked extension pointing to `dist/qa-capture` and refresh previously tested application tabs to remove older injected controls. ZIP installations must first replace the extracted files with the new archive. Standalone Screenshot downloads locally and needs no debugging session. Start testing retains Chrome's debugging notice, including during Pause; Finish/cancel detaches. Keep DevTools closed during testing. Choose Local · localhost:3000 in Settings while testing the web viewer locally. The existing file export/import and DevTools alternative remain available.

Text-position follow-up: the annotation input now anchors to the clicked image point using rendered-to-canvas coordinate mapping, stays inside image bounds where it fits, and follows editor resizing. Its ResizeObserver is removed when the form/editor closes. Actual Chrome checks verified a normal clicked point and the bottom/right edge, then passed the full screenshot/testing flow. Extension packaging tests, typecheck and targeted ESLint passed. Screenshot: `artifacts/qa-extension-ui/text-input-position.png`.

Chrome banner explanation: the extension still attaches only via `chrome.debugger.attach({tabId}, "1.3")`. Chromium creates a GlobalConfirmInfoBar indexed by extension ID, so its browser-wide wording does not imply attachment to every tab. This change does not suppress or bypass it. References: https://developer.chrome.com/docs/extensions/reference/api/debugger and https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/extensions/api/debugger/extension_dev_tools_infobar_delegate.cc . Jam documents tab video with associated logs, and XHR/fetch network data, with timing/CORS/static-asset/binary limits: https://jam.dev/docs/video and https://jam.dev/docs/devtools . Those docs do not justify claiming every activity or all response bodies are captured, or inferring Jam's complete internal architecture from its visible recording UI.

Card-drag follow-up: removed the visible grip and extra top spacing. The dock background/timer can be dragged with a grab cursor; pointer events originating from buttons/links/inputs are excluded. Pointer cancellation/lost capture resets dragging. The focusable card retains arrow-key movement.
